📊 1. Resumen Ejecutivo

Estratégico

El presente informe detalla el análisis de ingeniería para incorporar la pasarela de pagos Transbank Webpay Plus al ecosistema de agendamiento de citas Nicolet Estudio. Actualmente, las reservas se generan directamente en estado CONFIRMADA sin exigir validación de pago, lo que expone al negocio a inasistencias ("no-shows") y falta de trazabilidad financiera.

Impacto Operacional
-85%
Reducción estimada de inasistencias mediante prepago o seña obligatoria.
Compatibilidad Tarjetas
100%
Redcompra Débito, Tarjetas de Crédito (Visa/Mastercard/Amex) y Prepago.
Estándar API
REST v1.2
Seguridad HMAC/Headers sin SOAP obsoleto, cifrado TLS 1.2+.
Tiempo Estimado
3 Sprints
Desarrollo, testing de integración y certificación Transbank.
✅ Viabilidad Técnica Garantizada
El stack tecnológico existente (Spring Boot 3.2.5 con Java 17 y OpenFeign) es 100% compatible con los estándares REST de Transbank Developers. No se requiere refactorizar el núcleo del negocio, sino orquestar el agendamiento alrededor del ciclo de vida del pago.

🔍 2. Diagnóstico del Sistema Actual (AS-IS)

Diagnóstico

Tras auditar la base de código del proyecto Agendamiento-Cita-Main, se identificaron los siguientes aspectos arquitecturales clave:

Componente Estado Actual en el Código Brecha frente a Webpay Plus
Ciclo de Vida de Cita Al invocar CitaService.agendar(), la cita se persiste inmediatamente como EstadoCita.CONFIRMADA sin verificación económica. Debe introducirse el estado temporal PENDIENTE o retención de cupo con expiración (TTL) mientras el cliente paga en Transbank.
Entidad Pago / Transacción No existe ninguna tabla de transacciones bancarias, número de orden de compra ni código de autorización. Se requiere la entidad Pago para almacenar token, buy_order, authorization_code, card_number y montos.
Seguridad de Rutas (JWT) SecurityConfig exige JWT Bearer para todo /api/v2/nicolet/**, salvo autenticación y Swagger. El endpoint de retorno de Webpay (return_url) es invocado por la redirección del navegador del usuario sin headers Bearer. Debe ser público.
Dependencias HTTP El proyecto ya cuenta con spring-cloud-starter-openfeign versión 2023.0.1 y spring-boot-starter-web. Permite crear clientes REST limpios sin añadir librerías conflictivas o usar el SDK oficial de Transbank.
Frontend front/js/citas.js envía un POST asíncrono y muestra una alerta simple. Debe orquestar la redirección al formulario seguro de Transbank (auto-submit POST) y desplegar el comprobante regulatorio.

Endpoints Nucleares del Ciclo Webpay Plus

POST /rswebpaytransaction/api/webpay/v1.2/transactions

Crear Transacción: Inicializa el pago. Recibe buy_order, session_id, amount y return_url. Retorna un token de 64 caracteres y la url del formulario seguro de Transbank.

PUT /rswebpaytransaction/api/webpay/v1.2/transactions/{token}

Confirmar Transacción (Commit): Invocado por nuestro backend en cuanto el usuario vuelve vía return_url con token_ws. Confirma la autorización bancaria y obtiene código de autorización, últimos 4 dígitos y tipo de tarjeta.

GET /rswebpaytransaction/api/webpay/v1.2/transactions/{token}

Consultar Estado (Status): Permite verificar en cualquier momento el estado de la transacción (p. ej. en tareas de conciliación nocturna o ante caídas de conexión durante el commit).

POST /rswebpaytransaction/api/webpay/v1.2/transactions/{token}/refunds

Reembolso / Anulación (Refund): Permite reversar en línea un pago si la cita es cancelada dentro del plazo permitido por el estudio.

⚖️ 4. Estrategia de Implementación en Spring Boot 3

Decisión Técnica

Se evaluaron dos alternativas para conectar el backend con Transbank Developers:

Opción A: SDK Oficial Java Recomendado

com.github.transbankdevelopers:transbank-sdk-java:6.2.1

  • ✓ Mantenido y certificado directamente por Transbank Developers.
  • ✓ Credenciales de test e integración ya preconfiguradas.
  • ✓ Manejo automático de headers, URLs y serialización JSON.
  • ✓ Facilita pasar la homologación oficial de Transbank.
  • ✓ Código conciso: WebpayPlus.Transaction.buildForIntegration().

Opción B: FeignClient Nativo Alternativa

Uso de spring-cloud-starter-openfeign ya existente en pom.xml.

  • ✓ Cero dependencias externas adicionales en el proyecto.
  • ✓ Integración 100% nativa con interceptores de Spring Cloud.
  • ✕ Requiere construir a mano los DTOs completos y headers de TBK.
  • ✕ Mayor mantenimiento si Transbank actualiza campos en la API v1.2.
  • ✕ Mayor tiempo de desarrollo y pruebas manuales.
💡 Dictamen de Arquitectura
Se recomienda adoptar la Opción A (SDK Oficial Java 6.2.1) para la capa de servicios, complementada con un wrapper Spring Service con inyección de dependencias (IoC), garantizando máxima estabilidad y soporte en el proceso de certificación.

💾 5. Diseño de Base de Datos y Entidades

Persistencia

Para mantener la trazabilidad completa requerida por Transbank y el Servicio de Impuestos Internos (SII), se define la nueva entidad pago vinculada a cita:

Script DDL MySQL para la Tabla de Pagos

CREATE TABLE pago (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    cita_id BIGINT NOT NULL,
    buy_order VARCHAR(26) NOT NULL UNIQUE,
    session_id VARCHAR(61) NOT NULL,
    token_ws VARCHAR(64) UNIQUE,
    monto DECIMAL(10,2) NOT NULL,
    estado VARCHAR(30) NOT NULL DEFAULT 'INICIADO',
    codigo_autorizacion VARCHAR(10),
    ultimos_cuatro_digitos VARCHAR(4),
    tipo_pago VARCHAR(10), -- VN (Crédito), VD (Débito), VP (Prepago)
    codigo_respuesta INT,  -- 0 = Aprobada
    fecha_transaccion DATETIME,
    vci VARCHAR(10),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT fk_pago_cita FOREIGN KEY (cita_id) REFERENCES cita(id) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Entidad JPA: `Pago.java`

@Data
@Entity
@Table(name = "pago")
public class Pago {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @OneToOne(optional = false)
    @JoinColumn(name = "cita_id", nullable = false)
    private Cita cita;

    @Column(name = "buy_order", nullable = false, unique = true, length = 26)
    private String buyOrder;

    @Column(name = "session_id", nullable = false, length = 61)
    private String sessionId;

    @Column(name = "token_ws", unique = true, length = 64)
    private String tokenWs;

    @Column(nullable = false, precision = 10, scale = 2)
    private BigDecimal monto;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 30)
    private EstadoPago estado = EstadoPago.INICIADO;

    private String codigoAutorizacion;
    private String ultimosCuatroDigitos;
    private String tipoPago;
    private Integer codigoRespuesta;
    private LocalDateTime fechaTransaccion;
}

🔄 6. Flujo Transaccional Webpay Plus (Paso a Paso)

Diagrama

El proceso de pago sigue la coreografía segura definida por Transbank para evitar adulteraciones de montos o fraudes del lado del cliente:

1
Cliente Selecciona Hora y Servicio

El cliente en el frontend elige estilista, servicio y hora. Envía solicitud POST a /api/v2/nicolet/citas.

2
Backend Reserva Cupo en Estado PENDIENTE

Se validan colisiones de agenda. Se crea la cita en estado PENDIENTE con expiración temporal de 15 minutos.

3
Invocación WebpayPlus.Transaction.create()

Backend genera la orden de compra (buyOrder), define el monto exacto según catálogo (evitando alteración en JS) y llama a Transbank.

4
Redirección del Usuario al Formulario Transbank

El frontend recibe { url, token } y redirige automáticamente al usuario mediante auto-submit POST a url con parámetro token_ws.

5
Pago Seguro en Servidores Transbank

El usuario ingresa su tarjeta y autentica con su banco (Webpay Débito Redcompra o Crédito 3D Secure). Nuestro servidor nunca toca datos de tarjetas.

6
Retorno a return_url con token_ws

Transbank redirige el navegador a nuestro endpoint público: /api/v2/nicolet/pagos/webpay/retorno?token_ws=....

7
Commit Inmediato en Servidor

El backend invoca transaction.commit(token_ws) hacia Transbank. Si response_code == 0, la Cita pasa a CONFIRMADA y el Pago a APROBADO.

8
Despliegue de Comprobante / Voucher Oficial

Se redirige a la página final de éxito mostrando el voucher con código de autorización, datos de la cita y opción de descarga PDF.

⚠️ Manejo de Flujo Alternativo: Cancelación por el Usuario (Abort)
Si el usuario presiona "Anular compra y volver al comercio" dentro de Webpay, Transbank NO envía token_ws, sino los parámetros TBK_TOKEN, TBK_ORDEN_COMPRA y TBK_ID_SESION. El backend debe detectar estos parámetros, marcar el pago como ABORTADO, cancelar la cita y liberar de inmediato el cupo en la agenda.

💻 7. Implementación de la Capa de Servicios Spring

Código Java

A continuación se presenta la arquitectura del servicio especializado WebpayService: 

@Service
@Transactional
public class WebpayService {

    private final WebpayPlus.Transaction tx;
    private final PagoRepository pagoRepository;
    private final CitaRepository citaRepository;

    public WebpayService(PagoRepository pagoRepo, CitaRepository citaRepo) {
        this.pagoRepository = pagoRepo;
        this.citaRepository = citaRepo;
        // Inicialización en modo integración (Pruebas)
        this.tx = WebpayPlus.Transaction.buildForIntegration(
            IntegrationCommerceCodes.WEBPAY_PLUS,
            IntegrationApiKeys.WEBPAY
        );
    }

    public WebpayInitResponseDTO iniciarPago(Long citaId, String returnUrl) throws Exception {
        Cita cita = citaRepository.findById(citaId)
            .orElseThrow(() -> new RecursoNoEncontradoException("Cita no encontrada"));

        String buyOrder = "OC-" + cita.getId() + "-" + System.currentTimeMillis() % 10000;
        String sessionId = "SES-CLI-" + cita.getCliente().getId();
        double monto = cita.getPrecioFinal().doubleValue();

        // Llamada a Transbank
        WebpayPlusTransactionCreateResponse response = tx.create(buyOrder, sessionId, monto, returnUrl);

        // Registrar intento de pago
        Pago pago = new Pago();
        pago.setCita(cita);
        pago.setBuyOrder(buyOrder);
        pago.setSessionId(sessionId);
        pago.setTokenWs(response.getToken());
        pago.setMonto(cita.getPrecioFinal());
        pago.setEstado(EstadoPago.INICIADO);
        pagoRepository.save(pago);

        return new WebpayInitResponseDTO(response.getUrl(), response.getToken());
    }

    public VoucherDTO confirmarPago(String tokenWs) throws Exception {
        Pago pago = pagoRepository.findByTokenWs(tokenWs)
            .orElseThrow(() -> new IllegalArgumentException("Token no válido o sesión expirada"));

        // Confirmación formal con Webpay
        WebpayPlusTransactionCommitResponse commit = tx.commit(tokenWs);

        if (commit.getResponseCode() == 0 && "AUTHORIZED".equalsIgnoreCase(commit.getStatus())) {
            pago.setEstado(EstadoPago.APROBADO);
            pago.setCodigoAutorizacion(commit.getAuthorizationCode());
            pago.setUltimosCuatroDigitos(commit.getCardDetail().getCardNumber());
            pago.setTipoPago(commit.getPaymentTypeCode());
            pago.setCodigoRespuesta(commit.getResponseCode());
            pago.setFechaTransaccion(LocalDateTime.now());

            // Confirmar Cita
            Cita cita = pago.getCita();
            cita.setEstado(EstadoCita.CONFIRMADA);
            citaRepository.save(cita);
        } else {
            pago.setEstado(EstadoPago.RECHAZADO);
            pago.getCita().setEstado(EstadoCita.CANCELADA);
        }
        pagoRepository.save(pago);
        return toVoucher(pago, commit);
    }
}

🔒 8. Ajustes de Seguridad & Expiración Automática

Infraestructura

Ajuste en `SecurityConfig.java`

Dado que Transbank redirige el navegador web del usuario a la URL de retorno sin inyectar cabeceras Authorization: Bearer, la ruta de callback debe declararse como pública: 

// En SecurityConfig.java -> filterChain
.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/v2/nicolet/auth/**").permitAll()
    .requestMatchers("/api/v2/nicolet/pagos/webpay/retorno").permitAll() // <-- RUTA PÚBLICA DE RETORNO
    .requestMatchers("/doc/**", "/swagger-ui/**").permitAll()
    .requestMatchers("/api/v2/nicolet/**").authenticated()
)

Liberación de Cupos por Timeout (`@Scheduled`)

Si un cliente abandona la ventana del navegador antes de completar el pago, el cupo no puede quedar bloqueado indefinidamente. Se implementa un Cron Job en Spring Boot que libera las citas con más de 15 minutos en estado PENDIENTE: 

@Component
public class ExpiracionCitasJob {

    @Autowired
    private CitaRepository citaRepository;

    @Scheduled(cron = "0 */5 * * * *") // Ejecución cada 5 minutos
    public void expirarCitasNoPagadas() {
        LocalDateTime limite = LocalDateTime.now().minusMinutes(15);
        List<Cita> vencidas = citaRepository.findByEstadoAndCreatedAtBefore(EstadoCita.PENDIENTE, limite);
        
        for (Cita c : vencidas) {
            c.setEstado(EstadoCita.CANCELADA);
            c.setMotivoCancelacion("Expiró el tiempo límite para efectuar el pago en Webpay");
            citaRepository.save(c);
        }
    }
}
